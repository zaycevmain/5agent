# 5agent — мониторинг оборудования и процессов

Система из двух частей:

- **Агент** — один `.exe` для Windows. Отслеживает процессы, COM-порты,
  принтеры, RFID-считыватели и любое другое оборудование, и шлёт статус
  на сервер. Настраивается через окно (запустил → выбрал → свернул в трей).
- **Сервер** — папка, которую можно положить на Linux или macOS и запустить.
  Принимает heartbeat от агентов, показывает веб-дашборд с карточками
  устройств (зелёный/красный) и списком проблем, шлёт алерты в Telegram
  и/или на почту.

## Как это работает

1. На ПК с оборудованием ставишь и запускаешь агента.
2. В окне указываешь адрес сервера (IP или домен) и выбираешь процессы,
   COM-порты, принтеры, RFID и прочее оборудование (агент уже запущен и
   сам подхватит настройки).
3. Агент каждые N секунд проверяет всё выбранное и шлёт статус на сервер.
4. Сервер показывает устройства на дашборде. Если что-то отвалилось —
   статус краснеет, появляется запись в списке проблем, уходит алерт
   в Telegram/почту. Если агент перестал слать heartbeat — сервер помечает
   его офлайн и тоже алертит.

## Сборка агента (на Windows)

```bat
cd agent
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
build_agent.bat
```

Получится `agent\dist\5agent.exe` — один файл, переносится на любую машину.
Конфигурация хранится в `%APPDATA%\5agent\config.json`.

## Запуск сервера (Linux/macOS)

```bash
cd server
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp config.example.json config.json   # отредактировать: telegram/email, при желании auto_approve_agents
./run.sh
```

Дашборд: `http://<ip-сервера>:8080/`. Агент указывает этот адрес в поле
«Адрес сервера».

## Остановка сервера

- Запущен в терминале (`./run.sh`) — нажми **Ctrl+C**.
- Запущен в фоне/забыл терминал — найди и убей процесс:

```bash
pkill -f "uvicorn main:app"
```

Либо вручную: `lsof -i :8080` (узнать PID) → `kill <PID>`.

## Запуск через systemd (Linux)

Файл `server/5agent.service` — пример юнита. Подгони пути и пользователя,
затем:

```bash
# один раз: создать venv
cd server && python3 -m venv venv && venv/bin/pip install -r requirements.txt

sudo cp 5agent.service /etc/systemd/system/5agent.service
sudo systemctl daemon-reload
sudo systemctl enable --now 5agent
sudo systemctl status 5agent   # проверить
sudo systemctl stop 5agent     # остановить
sudo systemctl start 5agent    # запустить
```

## Домен и nginx (reverse-proxy)

Дашборд нельзя отдавать nginx'ом напрямую из `static/index.html` — странице
нужен API (`/api/state` и т.д.), который отдаёт FastAPI. Поэтому nginx
проксирует **все** запросы на приложение на порт 8080.

Пример конфига — `server/nginx.example.conf` (сразу только HTTPS/443:
HTTP на 80 просто редиректит на 443, TLS 1.2/1.3). Сначала получи сертификаты
(например `sudo certbot certonly --nginx -d monitoring.example.com`), затем
подставь пути `fullchain.pem`/`privkey.pem` в конфиг.

Агент указывает в поле «Адрес сервера» домен, например
`https://monitoring.example.com`. Если nginx на другой машине — в
`proxy_pass` ставишь `http://IP-сервера-5agent:8080` (сервер по умолчанию
слушает `0.0.0.0`, так что доступен извне).

### Пароль на дашборд

Проще всего — Basic Auth средствами nginx (в примере конфига уже есть).
Создай файл паролей и всё:

```bash
sudo htpasswd -c /etc/nginx/.htpasswd admin
sudo nginx -t && sudo systemctl reload nginx
```

В конфиге путь `/api/heartbeat` оставлен **без пароля** (агенты пушат туда),
а всё остальное (дашборд + админ-API) — за паролем. Если хочешь пароль
встроенный в само приложение (без nginx) — скажи, добавлю.

## Что умеет отслеживать агент

| Тип        | Что проверяется                                        |
|------------|--------------------------------------------------------|
| `process`  | запущен ли процесс (по имени `.exe`)                    |
| `window`   | открыто ли окно: по заголовку, и/или по процессу + командной строке |
| `com`      | активен ли COM-порт                                    |
| `printer`  | статус принтера: online/offline/error/пауза/«работать автономно» + нет бумаги, замятие, нет/мало тонера, открыта крышка, лоток заполнен, проблема с бумагой, ручная подача |
| `rfid`     | наличие RFID: USB-HID (VID/PID или имя), COM или TCP   |
| `custom`   | другое оборудование: TCP-порт, ping, USB-HID, COM, процесс, принтер |

### Как ведёт себя агент

- При запуске агент **сразу стартует** с предыдущими настройками (или пустыми),
  окно остаётся открытым.
- Крестик **сворачивает в трей** (мониторинг продолжается). Полный выход —
  только через меню трея «Выход».
- Кнопка «Запустить/Остановить» — ручное управление мониторингом.
- В шапке — индикатор связи: подключено / ожидает подтверждения / отключён
  сервером / нет связи.

## Зоны и группы (структура в админке)

Устройства можно раскладывать по иерархии **Зона → Группа (объект) → Устройство**:

- **Зона** — например «Вход 1», «Вход 2».
- **Группа/объект** — например «СКУД 1» (внутри зоны).
- **Устройство** — окно, COM-порт, принтер, RFID и т.д. (назначается в группу).

Секция «Структура» на дашборде: создаёшь зоны и группы, а в карточке устройства
выбираешь группу из выпадающего списка. Алерт и запись в проблемах тогда идут
с полным путём, например:

> Устройство **Вход 1 · СКУД 1 · Окно охраны**: ПРОБЛЕМА (окно не найдено)

Переименование (агент и устройства) — тоже в админке, кнопкой `✎`.

## Синхронизация устройств

Сервер держит актуальным список устройств агента: если ты удалил устройство из
агента, при следующем heartbeat оно исчезает и из админки (не висит красным).
Устройства у удалённого/отключённого агента остаются с последним статусом.

## Алерты

- Устройство перешло `ok → down` — алерт.
- Устройство перешло `down → ok` — алерт о восстановлении (можно отключить).
- Агент перестал слать heartbeat (офлайн) — алерт.
- Агент снова на связи — алерт о восстановлении.

Каналы: Telegram (бот) и/или email (SMTP). Настраиваются в `server/config.json`.

- **Email через Gmail** требует **App Password**, а не обычный пароль аккаунта:
  Google Аккаунт → Безопасность → включить Двухэтапную аутентификацию →
  «Пароли приложений» → создать пароль и вписать его в `password`.
- **Telegram** поддерживает прокси — поле `proxy` (например `socks5://user:pass@host:1080`
  или `http://host:3128`).
- `config.json` перечитывается сервером автоматически (каждые ~5 сек), перезапуск
  после правки не нужен.

## Авторизация агентов (подтверждение / отключение)

Агенты сами пушат данные на сервер (сервер их не опрашивает). У каждого агента
свой `agent_id` (генерится один раз, хранится в `%APPDATA%\5agent\config.json`).

Состояние агента на сервере:

- **active** — отслеживается, алерты работают.
- **pending** — ждёт подтверждения в админке. Данные видны, алертов нет.
- **disabled** — отключён из админки. Сервер отвечает агенту `403`, агент
  перестаёт спамить (лишь раз в минуту проверяет, не включили ли его обратно).

По умолчанию `auto_approve_agents: false` — новый агент появляется в секции
«Ожидают подтверждения», пока его не подтвердишь. Хочешь, чтобы новые агенты
включались сразу — поставь `"auto_approve_agents": true`.

В дашборде секции «Ожидают подтверждения» (Подтвердить/Отклонить) и «Отключены»
(Включить/Удалить). Если проект закончился — отключаешь агента (или удаляешь
совсем), и он деавторизуется.

Замечание про «остановил агент, а он ещё активен»: статус офлайн сервер ставит
не мгновенно, а после того как агент не прислал heartbeat дольше
`agent_offline_after_seconds` (по умолчанию 35 сек). Это не баг — таймаут на
случай кратковременных обрывов связи.
